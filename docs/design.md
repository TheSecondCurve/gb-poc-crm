# 决策日志 — 小红书账号矩阵经营管理系统

> 格式见 engineering-standards.md §7：每条记**决策 / 理由 / 推翻了什么旧决定**。逐条编号（K1、K2…），编号一经分配永不复用。AGENTS.md 与标准实例中的偏离标注引用本文件编号。

## K1（2026-09-11）本期范围扩至 S1~S9，超出标准 P0 硬性边界

- **决策**：本期实施 PRD §4.2 全部 9 个场景（S1~S9），P0/P1/P2 仅作为本期内实施顺序；标准 P0 边界本应是「第一大业务线 + 客户管理底座」（即 S1~S5）。
- **理由**：客户在需求访谈中明确拍板「这些需求我都需要，本期全部完成，不要让我拍优先级」；且本项目只有一条业务线，S6~S9 与 S1~S5 共用同一套数据模型，增量成本可控。
- **推翻**：requirement-interview 的「P0 硬性边界」收敛规则。

## K2（2026-09-11）审计日志库内永久保留

- **决策**：审计日志（删除、导出、令牌签发/吊销等关键操作）库内永久保留，不主动清理，随备份滚动。
- **理由**：permission-design.md 未给默认值；本项目数据量极小，审计回溯价值远高于存储成本。
- **推翻**：无（标准空白处的新决策）。

## K3（2026-09-11）内网明文 HTTP 起步 + 备份本地滚动 30 天、不做异地备份

- **决策**：暂不配域名，内网明文 HTTP（cookie 不 Secure 时应用只 warn 不拒启），后续有域名上 Caddy 自动证书；备份每日 `.backup` + gzip 本地滚动保留 30 天，不启用异地备份。
- **理由**：均在 deployment.md 默认方案的允许区间内；客户自有服务器、自行运维，机器层冗余客户自管。
- **推翻**：无（默认区间内的取值，成文备查）。

## K4（2026-09-11）agent-integration 安全清单补充 bash 3.2 多字节坑

- **决策**：向 docs/standards/agent-integration.md「安全细节清单」追加一条：macOS bash 3.2 下 `$VAR` 后紧跟全角字符会吃掉多字节首字节、`${X:-{{PLACEHOLDER}}}` 嵌套花括号被错误解析；skill 脚本一律 `${VAR}` 花括号形式 + if/else 赋值。
- **理由**：W3 实施 install.sh 时实测踩中（模板含 `{{BASE_URL}}` 占位符），不在原标准清单内；补入防止后续项目复发。
- **推翻**：无（对标准安全清单的补充，非推翻）。

## K5（2026-09-11）一键清除功能对业务表物理删除（软删规则的显式例外）

- **决策**：S11「一键清除全部业务数据」对 accounts/customers/ad_orders/account_investments/operating_expenses 五张业务表做物理清空（TRUNCATE 语义），不走软删；用户/设置/令牌保留，写审计日志。
- **理由**：该功能的用途就是演示数据清场/推倒重来，软删会让"已清除"的数据继续参与统计且无法达成"清空重来"；日常业务删除仍一律软删，不受影响。
- **推翻**：analytics-design.md / AGENTS.md「软删不硬删」规则在 S11 这一个管理员工具上的例外。
